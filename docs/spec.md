# my-memo 機能仕様書

## 1. 概要

### 1.1 サービス名

my-memo（仮称）

### 1.2 サービス概要

個人向けメモサービス。テキストメモ、画像付きメモ、URL 投稿（AI 要約メモ生成）を管理できる。

### 1.3 対象ユーザー

- 個人でメモを管理したいユーザー
- 複数デバイスからメモにアクセスしたいユーザー

### 1.4 開発思想

- 必要な機能のみをミニマムに実装
- 保守性・開発持続可能性を最重視
- ほぼノーコストで運用維持可能
- 可読性重視（いつ見ても内容が理解できる）
- UI/UX 重視（自分が使いたいと思えるものを作る）

## 2. 機能一覧

### 2.1 Phase 1: 認証機能

| 機能 ID  | 機能名             | 説明                                         |
| -------- | ------------------ | -------------------------------------------- |
| AUTH-001 | ソーシャルログイン | GitHub アカウントでログイン      |
| AUTH-002 | ログアウト         | セッションを終了してログアウト               |
| AUTH-003 | セッション維持     | ログイン状態を維持（D1データベースセッション） |

**補足**

- ID/パスワードによる認証は実装しない
- ログインしていない場合、すべての画面でログイン画面にリダイレクト

### 2.2 Phase 2: メモ基本機能

| 機能 ID  | 機能名       | 説明                       |
| -------- | ------------ | -------------------------- |
| MEMO-001 | メモ作成     | 新規メモを作成する         |
| MEMO-002 | メモ一覧表示 | 自分のメモを一覧で表示する |
| MEMO-003 | メモ詳細表示 | メモの内容を詳細表示する   |
| MEMO-004 | メモ編集     | 既存メモの内容を編集する   |
| MEMO-005 | メモ削除     | メモを削除する             |

**補足**

- メモ本文の文字数上限: 10,000 文字
- 自分のメモのみ閲覧・編集・削除可能（認可不要）

### 2.3 Phase 3: カテゴリ・タグ機能

| 機能 ID    | 機能名                | 説明                                                               |
| ---------- | --------------------- | ------------------------------------------------------------------ |
| CAT-001    | カテゴリ作成          | 新規カテゴリを作成する                                             |
| CAT-002    | カテゴリ編集          | カテゴリ名を編集する                                               |
| CAT-003    | カテゴリ削除          | カテゴリを削除する                                                 |
| CAT-004    | カテゴリ割り当て      | メモにカテゴリを割り当てる（単一選択）                             |
| TAG-001    | タグ割り当て/自動作成 | メモにタグを割り当てる（複数選択可）。既存タグがない場合は自動作成 |
| FILTER-001 | カテゴリフィルタ      | カテゴリでメモ一覧を絞り込む                                       |
| FILTER-002 | タグフィルタ          | タグでメモ一覧を絞り込む                                           |

**補足**

- カテゴリ: 1 つのメモに 1 つのカテゴリのみ設定可能
- タグ: 1 つのメモに複数のタグを設定可能
- タグは独立した作成機能なし。メモ作成/編集時に入力したタグが既存のものでなければ自動的に作成される
- タグの編集・削除機能は提供しない（運用負荷軽減のため）
- カテゴリ・タグはユーザーごとに管理
- カテゴリ・タグの作成数に上限なし

### 2.4 Phase 4: 画像付きメモ機能

| 機能 ID | 機能名           | 説明                           |
| ------- | ---------------- | ------------------------------ |
| IMG-001 | 画像アップロード | メモに画像を添付する           |
| IMG-002 | 画像表示         | メモに添付された画像を表示する |
| IMG-003 | 画像削除         | メモから画像を削除する         |

**補足**

- 1 つのメモに最大 4 枚まで画像を添付可能
- 対応フォーマット: JPEG, PNG, GIF, WebP
- ファイルサイズ上限: 5MB/枚（予定）

### 2.5 Phase 5: URL 投稿・AI 要約機能

| 機能 ID | 機能名         | 説明                                                             |
| ------- | -------------- | ---------------------------------------------------------------- |
| URL-001 | URL 投稿       | URL 投稿専用画面から URL を送信し、AI 要約を生成してメモとして保存する |
| URL-002 | コンテンツ取得 | URL から Web ページの内容を取得する                              |
| URL-003 | AI 要約生成    | 取得したコンテンツを AI で要約し、タイトル・要約を生成する        |
| URL-004 | 要約表示       | 生成された要約をメモと共に表示する                               |

**補足**

- URL は 1 メモにつき 1 つ
- URL 投稿時に **カテゴリ選択（任意）** を行える（`category_id` を送信）
- 要約は**同期的に生成して保存**する（POST `/memos/url` で生成→保存→リダイレクト）
- 生成された要約は `content` に保存し、`ai_generated` フラグを `1` に設定する。手動での再生成も可能

## 4. ユーザーフロー

### 4.1 ログイン〜メモ作成

1. ユーザーがサービスにアクセス
2. 未ログインの場合、ログイン画面（SCR-001）にリダイレクト
3. GitHub でログイン
4. メモ一覧画面（SCR-002）に遷移
5. 「新規作成」ボタンをクリック
6. メモ作成/編集画面（SCR-003）で内容を入力
7. 「保存」をクリックしてメモを保存
8. メモ一覧画面（SCR-002）に戻る

### 4.2 メモの編集

1. メモ一覧画面（SCR-002）またはメモ詳細画面（SCR-004）から「編集」をクリック
2. メモ作成/編集画面（SCR-003）で内容を編集
3. 「保存」をクリックして変更を保存
4. メモ詳細画面（SCR-004）またはメモ一覧画面（SCR-002）に戻る

### 4.3 メモのフィルタリング

1. メモ一覧画面（SCR-002）を表示
2. カテゴリまたはタグを選択
3. 選択した条件に一致するメモのみ表示

### 4.4 URL 投稿・AI 要約

1. メモ作成/編集画面（SCR-003）で URL を入力し（任意で `category` を選択）、送信または保存を行う
2. サーバー側で URL へアクセスし、同期的にコンテンツを取得・AI による要約生成を行う
3. 生成されたタイトル・要約を `memos` として保存する（`content` に要約、`ai_generated` を `1`、`category_id` は指定があれば保存）
4. 保存完了後、メモ詳細画面（SCR-004）へリダイレクトし、要約が即時表示される
5. 必要に応じて「要約を再生成」ボタンを用意して手動再生成を行えるようにする（再生成時も `content` を更新し `ai_generated` を維持する）

## 5. 非機能要件

### 5.1 認証・認可

- **認証**: 必須（ソーシャルログインのみ）
- **認可**: Better Auth Adminプラグインの`user`/`admin` roleで管理者権限を判定
- **管理者設定**: 最初の管理者はDB操作で指定し、以後の変更は管理者専用機能から行う
- **標準管理API**: Better Authの標準管理変更エンドポイントは無効化し、アプリ独自の管理APIに限定する
- **プラン**: ユーザーごとに1つのプランを割り当てる。初期seedではfree（メモ100件、AI要約10回/月）を登録する。新規ユーザーには、`plans.is_default = 1`かつ有効なプランを自動割り当てする
- **プラン変更**: DB操作または管理者による変更。変更は即時反映し、既存データは削除しない
- **上限期間**: メモは保存総数、AI要約はUTC月次回数
- **上限超過**: 既存データを保持したまま、新規の対象操作を拒否する

### 5.2 セキュリティ

- HTTPS 通信必須
- セッション管理: D1データベースセッション（Better Auth、HTTP-only Cookie）
- データ暗号化: オプション（開発コストに応じて検討）

### 5.3 データ保持

- ユーザーがログインすれば、どのデバイスからでも自分のメモにアクセス可能

## 6. 前提条件・制約

- MPA（Multi Page Application）として実装
- リアルタイム同期機能なし
- 全文検索機能なし（MVP 時点）
- 対応ブラウザ: モダンブラウザ（Chrome, Firefox, Safari, Edge 最新版）
